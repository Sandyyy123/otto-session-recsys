Motivation

Most e-commerce traffic is anonymous or weakly identified. Classical user-based collaborative filtering needs a stable user identity to accumulate history; that identity is often missing. Session-based recommendation predicts the next item from the within-session sequence alone, which is the production reality for the majority of impressions on any large retailer.

Pairs with project 13 (H&M). H&M is collaborative filtering on persistent user history. OTTO is sequence modelling on within-session events. Together they cover the two production paradigms in modern recsys.

The OTTO competition adds a multi-objective twist. Instead of a single next-event Recall@20, the score is a weighted sum across three event types:

score = 0.10 * Recall@20(clicks)
      + 0.30 * Recall@20(carts)
      + 0.60 * Recall@20(orders)

Orders are weighted six times higher than clicks because orders are the only event that closes the loop between recommendation and revenue.

Data

OTTO Recommender Systems Dataset, released for the 2022 Kaggle competition. Four weeks of anonymised browsing and purchase events from OTTO's German storefront.

Methods

Co-visitation baseline

For every ordered pair of events (a, b) in the same session within a 1-hour window, increment three sparse counters keyed on the source aid: a clicks counter, a carts counter, an orders counter. Increments are weighted by the type of event b (1.0 / 6.0 / 3.0). After all train sessions are processed, prune to the top 40 targets per source per matrix.

At inference, take the K=30 most recent events of the active session, look up each event's top neighbours in the matrix that matches the target task, aggregate scores with a recency decay, return top 20.

SASRec multi-task transformer

Causal self-attention over the session sequence, with three task-specific projection heads sharing a backbone. Training uses sampled-softmax loss with 200 uniform negatives per row, weighted by the official 0.10 / 0.30 / 0.60 schedule.

seq -> item_emb + pos_emb -> [transformer x N] -> last_pos
                                                        |
                          +-----------+-----------------+-----------+
                          |           |                 |
                       clicks_head  carts_head      orders_head
                          |           |                 |
                          v           v                 v
                       softmax(@ item_emb table)  -- top-20 each

Default hyperparameters: d_model=64, n_heads=2, n_layers=2, max_seq_len=50, batch=512, AdamW lr=1e-3, 3 epochs.

Discussion

Why the baseline is competitive

Co-visitation captures the strongest signal in the dataset: items that users buy together in the same session are likely to be the next items bought together. Per-event-type weighting lets the same matrix serve all three Recall@20 prediction tasks, which is the small-but-decisive advance over Sarwar 2001.

Why the transformer is expected to win

End-to-end optimised item embeddings, continuous positional reasoning instead of hand-crafted recency decay, and a shared backbone that lets order signal benefit from the abundant click signal.

Phase 2 directions

  • Two-stage retrieve-then-rerank, with co-visitation as retriever and SASRec as reranker (Covington 2016 pattern)
  • MMoE-style multi-task routing to reduce gradient interference (Ma 2018a)
  • BERT4Rec masked-language-modelling pretraining (Sun 2019)
  • Importance-weighted negative sampling for popularity-bias correction (Yi 2019)
  • FAISS or ScaNN approximate nearest-neighbour serving for production deployment
  • Graph methods: SR-GNN (Wu 2019), KGAT (Wang 2019)

Conclusion

Two reproducible reference systems for OTTO's multi-objective session-based recommendation task. The co-visitation baseline is the strongest non-neural option and serves as a candidate-generation oracle. The SASRec multi-task transformer adds learned item embeddings, continuous recency, and shared backbone gains across the three event heads. Both scripts are runnable and unexecuted; running them in the main session populates the placeholder cells above with measured numbers.
